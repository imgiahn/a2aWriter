# 창업공고 분석노트 — 작성 가이드

## 블로그 포지션

"공고를 복사하는 블로그"가 아니라 "창업자가 지원 여부를 판단할 수 있게 해석해주는 블로그".
K-Startup 및 창업지원사업 공고를 예비창업자·초기창업자 입장에서 해석한다.

## 주요 독자

- 예비창업자 / 초기창업자 / 3년·7년 이내 창업기업
- 정부지원사업을 처음 준비하는 사람
- K-Startup 공고를 봐도 무슨 말인지 어려운 사람
- 사업계획서를 처음 써보는 사람
- AI/SaaS/콘텐츠/교육/제조/지역 기반 창업자

## 글 구조 (순서 고정)

### 1. 공고 한 줄 요약
이 사업이 누구를 위한 사업인지 한 문장으로 설명한다.

### 2. 핵심 정보 요약 (<h2>핵심 정보 요약</h2>)
표 형태로 정리한다. 포함 항목: 사업명 / 주관기관 / 신청기간 / 신청 마감일 / 지원대상 / 지원내용 / 지원규모 / 신청방법 / 공고 확인 링크 / 주의할 점.

### 3. 지원 대상 분석 (<h2>지원 대상 분석</h2>)
아래 항목을 공고 기준으로 확인한다: 예비창업자 가능 여부 / 개인사업자 가능 여부 / 법인사업자 필수 여부 / 창업연차 제한 / 지역 제한 / 업종 제한 / 기술 분야 제한 / 제외 대상.
데이터가 없는 항목은 생략한다.

### 4. 지원 내용 분석 (<h2>지원 내용 분석</h2>)
해당되는 항목만 설명한다: 사업화 자금 / 멘토링 / 교육 / 입주공간 / 투자연계 / 판로지원 / 해외진출 / 네트워킹 / 인증·실증·PoC 지원.

### 5. 이런 사람에게 추천 (<h2>이런 사람에게 추천</h2>)
구체적인 독자 유형을 제시한다. 예: "아직 법인 설립 전이지만 아이템이 구체적인 예비창업자", "MVP는 있지만 사업화 자금이 필요한 초기창업자".

### 6. 이런 사람은 비추천 (<h2>이런 사람은 비추천</h2>)
조건이 맞지 않거나 준비가 어려운 대상을 설명한다. 예: "아직 아이템이 추상적인 사람", "마감일까지 서류 준비가 어려운 사람".

### 7. 사업계획서 작성 포인트 (<h2>사업계획서 작성 포인트</h2>)
이 공고에서 강조하면 좋을 만한 내용을 정리한다.
"무조건 해야 한다"가 아니라 "강조하는 것이 유리할 수 있다"는 식으로 작성한다.
포함 가능 항목: 문제 정의 / 고객·시장 분석 / 기존 대안의 한계 / 제품·서비스 차별성 / 실행 계획 / 매출화 가능성 / 팀 역량 / 기술성 / 지역 기여도 / 고용 창출 가능성 / 수출·글로벌 확장 가능성 / 실증·PoC 계획.

### 8. 준비 난이도 (<h2>준비 난이도</h2>)
낮음 / 중간 / 높음 중 하나로 평가한다.
평가 기준: 제출 서류 수 / 사업계획서 난이도 / 증빙자료 필요 여부 / 발표평가 여부 / 지원 자격 제한 / 마감까지 남은 기간.

### 9. 최종 판단 (<h2>최종 판단</h2>)
아래 형식으로 정리한다:
- 추천도: ★☆☆☆☆ ~ ★★★★★
- 준비 난이도: 낮음/중간/높음
- 추천 대상: ○○한 창업자
- 핵심 준비물: 사업계획서, 증빙서류, 발표자료 등
- 가장 중요한 포인트: ○○

### 10. 공식 공고 확인 안내 (<h2>공식 공고 확인 안내</h2>)
마지막에는 반드시 공식 공고문 확인을 안내한다.
K-Startup 링크(https://www.k-startup.go.kr)를 포함한다.

## 문체 규칙

- 친절하지만 현실적으로 작성한다.
- 창업자가 빠르게 판단할 수 있게 쓴다.
- 문단은 짧게 쓴다.
- 표를 적극 사용한다.
- 너무 딱딱한 행정문체를 피한다.
- "무조건 선정됩니다", "반드시 지원하세요" 같은 과장 표현 금지.
- "지원해볼 만합니다", "조건이 맞는다면 검토할 만합니다"처럼 신중하게 작성한다.
- 원문 문장을 그대로 복사하지 말고 재해석한다.

## 절대 금지사항

- 공고 원문 단순 복붙 금지
- 공식 기관처럼 보이는 표현 금지
- 선정 가능성을 단정하는 표현 금지
- 지원금 수령 가능하다고 단정 금지
- 확인되지 않은 지원금액/마감일/조건 작성 금지
- 마감일이 지난 공고를 진행 중인 것처럼 작성 금지
- K-Startup 공식 블로그처럼 오해될 수 있는 표현 금지
- 데이터가 없을 때 그 사실을 본문에 언급하는 것 금지 ("데이터가 확인되지 않습니다" 등 — 없으면 해당 항목 생략)
- 공고 원문에 없는 정보 추측 금지 (불확실한 내용은 "공식 공고문 확인 필요"라고만 표시)
