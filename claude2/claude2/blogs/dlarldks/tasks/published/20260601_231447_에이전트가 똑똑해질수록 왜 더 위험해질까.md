<p>솔직히 말하면, 요즘 AI 에이전트 뉴스들을 보면 묘한 불안감이 먼저 듭니다. 처음엔 “와, 이제 알아서 일하는구나” 싶었는데, 요즘은 그 반대예요. 똑똑해질수록 더 많이 움직이고, 더 많이 움직일수록 사고가 커집니다. 이번에 나온 사례들을 보면 핵심은 아주 단순합니다. 문제는 프롬프트가 아니라, 에이전트가 <strong>무슨 도구를 어떤 권한으로 쓰는가</strong>입니다.</p>

<h2>시트 한 장이 아니라, 계정 전체가 흔들린다</h2>
<p>Prompt Armor가 공개한 <em>ChatGPT for Google Sheets</em> 유출 사례를 보면 이게 얼마나 현실적인지 바로 감이 옵니다. 단일 시트에 들어간 indirect prompt injection만으로 워크북 여러 개가 털릴 수 있고, 심지어 피싱 오버레이까지 붙을 수 있었다고 하거든요. 저는 이걸 보면서 “아, 공격자는 모델을 속이는 게 아니라 도구 사용 흐름을 노리는구나” 싶었습니다. 예전 보안은 문을 잠그는 데 집중했다면, 지금은 집 안의 서랍과 금고까지 다 열쇠가 연결된 느낌이에요.</p>

<p>이게 무서운 이유는 권한이 넓을수록 생산성이 같이 오른다는 데 있습니다. 에이전트가 여러 워크북을 읽고 정리해 주면 편하죠. 그런데 한 번 뚫리면 피해 범위도 그만큼 커집니다. 그러니까 “똑똑한 AI”가 아니라 “권한이 큰 AI”가 진짜 리스크인 셈입니다.</p>

<h2>그래서 요즘은 성능보다 ‘중간 통제’ 얘기가 나온다</h2>
<p>이 흐름에서 흥미로웠던 게 Microsoft Agent Governance Toolkit 논의였습니다. 요지는 에이전트가 도구를 보자마자 바로 실행하지 말고, 정책과 승인, 감사로그, 위험도 판단 같은 중간 레이어를 한 번 더 거치게 하자는 겁니다. 쉽게 말해, 자동으로 차를 몰게 하더라도 신호등과 속도제한, 블랙박스가 같이 있어야 한다는 거죠.</p>

<p>저는 개인적으로 이 부분이 가장 중요해졌다고 봅니다. 예전엔 모델이 얼마나 잘 답하느냐가 제품 경쟁력이었는데, 이제는 “어떤 행동을 허용하고, 무엇을 기록하고, 어디서 멈추게 할 것인가”가 더 중요해졌어요. AI가 일 잘하는 비서가 되려면, 그 전에 통제 가능한 직원이어야 하니까요.</p>

<h2>도구가 많아질수록 오히려 컨텍스트도 흔들린다</h2>
<p>재밌는 건 성능 이슈도 보안이랑 연결된다는 점입니다. Hermes Agent의 Tool Search처럼 도구를 더 잘 찾게 해주는 시도는 분명 유용하지만, 동시에 도구가 너무 많아지면 모델의 컨텍스트가 금방 지쳐버립니다. 도구를 잘못 고르면 오작동이 나고, 그 오작동은 곧 권한 오남용으로 이어질 수 있죠. 결국 “더 많이 연결하는 것” 자체가 답은 아닙니다.</p>

<p>여기에 GitHub Copilot의 토큰 기반 과금 논란까지 겹치면 그림이 더 분명해집니다. 에이전트가 실무에 깊게 들어올수록 비용은 예측 가능해야 하고, 무엇보다 회사는 “얼마나 많이 쓸 수 있나”보다 “어디까지 써도 되는가”를 먼저 묻게 됩니다. 이건 단순한 기능 경쟁이 아니라 운영 경쟁이에요.</p>

<p>결국 에이전트 시대의 병목은 모델 지능이 아닙니다. 도구 호출 경로, 승인 체계, 감사 로그, 비용 통제. 솔직히 말하면, 앞으로 진짜 강한 제품은 제일 똑똑한 모델이 아니라 제일 잘 멈추는 시스템일지도 모르겠습니다. 그게 좀 아이러니하죠.</p>
